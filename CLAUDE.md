# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

**House rule for this file:** state the current fact, cite the decision (`Dnn`) or backlog item
(`NEW-nn`) that holds the history, and never quote a count you did not derive. When a check prints its
own count, read that line, not a number written here. Counts copied into this file have gone stale
again and again.

## What this directory is

The **HealthConnect / Abofonsa BridgeCare Marketplace**: a two-sided brokerage connecting
*non-medical* health professionals (trainers, nutritionists, therapists, home carers) with customers.
It was a design package until 24 August 2026 and is now a partly-built JHipster estate.

```
gateway/    healthconnectGateway   MongoDB, reactive    RUNS — routes public reads to catalog
catalog/    healthconnectCatalog   PostgreSQL 17        BUILT — seeded, serving, verified
booking/    healthconnectBooking   PostgreSQL 17        BUILT — aggregate seeded, state machine live
messaging/  healthconnectMessaging PostgreSQL 17        BUILT — seeded, consumes booking events
payout/     healthconnectPayout    PostgreSQL 17        BUILT — ledger seeded, earnings verified
jdl/        the five JDL files — the model of record
deploy/     deploy-dev.sh, deploy-prod.sh, docker/, demo/, observability/, prod-server/
quality/    the jacserver quality stack — compose, vhost, startup.sh
docs/       the spec, the decisions log, the prototype
web/        hcMarket   Angular 21, client-only   THREE PUBLIC SCREENS — rendered from the live estate
api/        EMPTY. Not created by this build; left alone deliberately.
```

The five backend applications are **Spring Boot 4.0.7 on Java 25**, generated by **JHipster 9.2.0**.

### `web/` — the marketplace client (D101, D103)

`web/` is a sixth application and **not one of the five**. It is a **client-only** JHipster 9.2.0 /
Angular 21.2.17 app (`skipServer: true`, `databaseType: no`), so it has no `pom.xml`, no `mvnw` and no
`.java` files. It lives in its own directory so the gateway is never regenerated: `--force` there would
bring back D61's `admin`/`admin` credential and strip the OTel block out of `pom.xml`.
`enableTranslation` is on and `jhiPrefix` is `abm` (D92 §2). The gates are `npm run lint`,
`prettier:check`, `npm test`, `webapp:prod` and `check:built-assets`, in that order, and `build.yml`'s
`web` job runs exactly those.

`app/marketplace/` holds **Discover (`/`), Browse (`/browse`) and the public profile
(`/professionals/:ref`)**. All three have been rendered from the running quality estate
(`HC_GATEWAY_PORT=15509 npm start`) and read in headless Chrome. They need no token, because every
endpoint behind them is `permitAll` in catalog. **Still undecided:** which origin a built bundle
addresses. That is Phase 5's question, and cheap, because `SERVER_API_URL` is `''` and every URL is
relative.

- ⚠ **The card's headline price is `fromPaidPriceMinor`, and it must stay that way** (D100, D103 §2).
  `fromPriceMinor` is the literal minimum including free services. For p12 and p13 it is 0, while their
  cheapest purchasable services are ₵280 and ₵420, so rendering it would print "from ₵0". It is also
  not what `maxPriceMinor` filters on. `hasFreeService` is a marker beside the price ("Free service
  available"); it never calls the service an intro. There are four price states:
  - paid price present → that price
  - paid price null, marker set → **`Free`** (NEW-78)
  - paid price null, no marker → **"Price on enquiry"**
  - `rating` null → **"No reviews yet"**, never five empty stars.
- ⚠ **`app.routes.ts` must list the marketplace before `entity.routes`, and getting it wrong fails
  silently.** `entity.routes` is a generated empty array (`/* needle */`) behind `path: ''`. If it comes
  first it consumes `/`, finds no child and does not backtrack, so the landing page is an empty outlet.
  Every gate stays green and no console error appears. `app/app.routes.spec.ts` asks the router and goes
  red. Do not reorder the two entries, and do not delete the entities one: its needle is where
  generated entity routes land.
- ⚠ **Never bind `[value]` on a `<select>` whose options come from an `@for`; put `[selected]` on the
  option instead** (D103 §13a). Angular writes the value before the options exist, so the browser
  selects option 0 and nothing corrects it. The result is a correct result list under a menu reading
  "Most relevant". This only happens on first render, which covers every shared link, reload and
  back-navigation. No assertion over the signal can see it; Browse's spec asserts the **rendered**
  selection.
- **Three guards will fire on the next screen. Do not loosen any of them** (D103 §9):
  - `endpoint-construction.spec.ts` keys on the method name, so it flags a literal
    `params.get('ref')`. Use `app/marketplace/route-params.ts` instead.
  - `anyComponentStyle` is 2 kB warn / 4 kB error. Meet it by hoisting shared primitives into
    `content/scss/global.scss`, not by raising the budget. The three page stylesheets exceed the
    *warning* deliberately.
  - A `subscribe({ next })` with no `error` arm rethrows as an uncaught exception.
- **Every screen branches on three states** through `app/marketplace/load-state/`: loading, failed
  with a retry, and empty with the screen's own words. The prototype has markup for none of them. A 404
  and a 502 render identically on the profile, deliberately.
- **No screen states the commission rate or the cancellation window** (D57, NEW-83). Both are
  per-estate config and no anonymous endpoint publishes them. The guard is
  **`terms-are-not-quoted.spec.ts`**, which reads the **files** (every `i18n/en/*.json` value and every
  template under `app/`). A TestBed with no bundle loaded renders translation **keys**, so a template's
  fallback prose is never in the DOM. **Any spec asserting over rendered text must call
  `marketplace.fixtures.ts`'s `loadEnglish()`.** The ban covers all six of the prototype's
  rate-and-window sentences, including "Free up to 24 hours before the session" (D103 §14), which is
  caught because `free` is in both hours patterns. Do not drop the noun requirement instead: that would
  flag `reset.json`'s correct "valid for 24 hours". The ban deliberately lets a professional's own
  "88% rebook" through. The template list is four named files,
  not a `> 4` count.
- **The seeded availability is anchored at 2026-08-10**, so every profile's ten-day strip shows its
  empty state on quality. That is NEW-84, not a client bug.
- **Cypress has never run**, nothing from `web/` is deployed, and **no human has looked at the
  layout.** A DOM dump establishes figures and states, not legibility.

## Commands

Each app is a **standalone Maven project**, with no aggregator pom. Always `cd` into the app first.

```bash
export JAVA_HOME=/usr/lib/jvm/jdk-25.0.2-oracle-x64   # see the JDK trap below
cd catalog && ./mvnw clean verify                      # NEVER an incremental build
cd catalog && ./mvnw -Dtest=SecurityUtilsUnitTest test  # one unit test  (surefire)
cd catalog && ./mvnw -Dit.test=ReviewResourceIT verify   # one integration test (failsafe)
cd catalog && ./mvnw -q package -DskipTests             # jar only

# Regenerate an app from its JDL — read "the regeneration hazard" first, and
# "Generating inside an agent worktree" before running ANY jhipster command from .claude/worktrees/
cd catalog && jhipster jdl ../jdl/catalog.jdl --skip-install --skip-git --force

# The marketplace client (D101). Node 24.18.0 — `nvm use` reads web/.nvmrc. No mvnw, no Java.
cd web && npm ci
cd web && npm run lint && npm test          # `pretest` runs lint, so `npm test` covers both
cd web && npm run prettier:check            # lint does NOT cover .scss/.md/.json
cd web && npm run webapp:prod && npm run check:built-assets   # build, THEN assert over the output
cd web && HC_GATEWAY_PORT=15509 npm start   # ⚠ the default 8080 is abofonsa_api on this box

# The seed is REGENERATED, never edited. Asserts the prototype's figures; refuses to write on drift.
node deploy/demo/extract-seed.mjs

# The shared plane FIRST — this repository runs no broker and no Consul of its own (D27)
(cd ~/webroot/01-healthconnect/hc-infra && ./startup.sh)

# The whole estate. Both secrets are REQUIRED with no default (D35). Keep them in deploy/.env:
# a new pepper orphans every erasure alias already written; a new key invalidates every token.
JWT_BASE64_SECRET=$(head -c 64 /dev/urandom | base64 -w0) \
HC_PRIVACY_PEPPER=$(head -c 32 /dev/urandom | base64 -w0) ./deploy/deploy-dev.sh up
./deploy/deploy-dev.sh status | logs | down --clean
./deploy/deploy-prod.sh --tag 1.4.0 --dry-run          # safe; prints everything, changes nothing
```

**Test selection.** Surefire excludes `**/*IT*` and failsafe includes them, so `./mvnw test` runs no
integration test and `verify` runs both. Naming the wrong one here **errors loudly** (`No tests
matching pattern ... were executed!`).

**Published ports collide on this workstation** (`abofonsa_api` holds 8080, and the sibling quality
stacks hold others). Every published port can be overridden, and `deploy-dev.sh` reads the same
variables for its health gates. Override them together:

```bash
export HC_GATEWAY_PORT=18200 HC_CATALOG_PORT=18201 HC_BOOKING_PORT=18202 \
       HC_MESSAGING_PORT=18203 HC_PAYOUT_PORT=18204
```

`MAILPIT_HTTP_PORT` (quality, default **18104**) and `HC_MAILPIT_HTTP_PORT` (dev, default 8025) are
the mail catcher's web UI (D94). **Its SMTP port is not published on either estate**: an
unauthenticated SMTP listener on the LAN is an open relay.

Only the host mapping moves. Inside the containers every service listens on **8080** (compose sets
`SERVER_PORT: 8080`, overriding the JDL's per-service ports, which exist for side-by-side local runs).
`SPRING_CLOUD_CONSUL_PORT` is always 8500 inside.

**Shared-plane overrides.** This repository publishes no Consul or Kafka port. `hc-infra` publishes
them once: **18510** (Consul UI) and **19192** (broker, from the host). `HC_SHARED_CONSUL`,
`HC_SHARED_KAFKA`, `HC_SHARED_NETWORK` and `HC_OTEL_NETWORK` choose the plane in dev and quality alike
(D66). Each is read by the script *and* the compose file. Set them together or not at all; unset is the
estate `hc-infra` runs. The hostnames **must be container names**, because preflight `docker exec`s
them. `shared-kafka` and `shared-consul` resolve but are refused. The value carries no port (compose
appends it).

**Walking the account lifecycle** (D94). No real provider is needed:

```bash
curl -s -o /dev/null -w '%{http_code}\n' -H 'Content-Type: application/json' \
  -X POST http://127.0.0.1:15509/api/register \
  -d '{"login":"walk.one","email":"walk.one@example.test","password":"at-least-four-chars","langKey":"en"}'
curl -s http://127.0.0.1:18104/api/v1/messages | jq -r '.messages[0].ID'     # the catcher's API
curl -s http://127.0.0.1:18104/api/v1/message/<ID> | jq -r '.Text'           # the link, and the key in it
curl -s -o /dev/null -w '%{http_code}\n' 'http://127.0.0.1:15509/api/activate?key=<KEY>'
```

The mailed link (`${baseUrl}/account/activate?key=…`) is a frontend route and answers **401** on an
API-only estate (NEW-60). `GET /api/activate?key=…` is the one that answers 200. A registered but
unactivated account answers **500** to its own correct password (NEW-61).

**Running `catalog` alone** is the fastest loop. It needs neither Consul nor Kafka:

```bash
docker run -d --name hc-catalog-db -p 5432:5432 \
  -e POSTGRES_USER=healthconnectCatalog -e POSTGRES_DB=healthconnectCatalog \
  -e POSTGRES_HOST_AUTH_METHOD=trust postgres:17
java -jar catalog/target/healthconnect-catalog-0.0.1-SNAPSHOT.jar \
  --spring.profiles.active=test,dev \
  --spring.cloud.consul.enabled=false --spring.cloud.discovery.enabled=false \
  --healthconnect.seed.enabled=true \
  --healthconnect.seed.file=$PWD/deploy/demo/seed-data.json \
  --healthconnect.seed.anchor-dates=true --server.port=8081
```

With no broker it logs Kafka `MessageDeliveryException` on a timer. That is noisy and harmless, and it
is the *only* sign a service has no broker. **Startup takes about 2 minutes without the OTel agent and
8–11 minutes with it** (D89: 641s for payout from container start). `quality/compose.yml`'s
`start_period` is 300s, and `quality/startup.sh` polls 200 times (800s), deliberately above docker's
own 700s.

## The deploy scripts: preflight, probes and the health gate

The rules below were each learned from a fail-open. They are recorded in D65–D81; read those before
changing either script.

- **The shared-plane preflight checks both that the broker is running and that it is on the network
  this stack joins** (D66). It is `check_shared_plane` in `quality/startup.sh` and **`shared_plane`** in
  `deploy-dev.sh` (D69, NEW-29). The names differ, so a grep carried from one file finds nothing in the
  other; CI's membership check walks `script:function` pairs for that reason. Both are fatal.
- **CI pins the exact set of `deploy-dev.sh` branches that call `preflight`: `{up, reseed, restart}`**
  (D69 §10). `down`, `status` and `logs` must not call it, so a broken plane cannot wedge teardown. The
  check only sees a **direct** call in the branch, so keep it direct; a wrapper function is invisible.
- **A `die` may not fold a docker read; a `warn` or a poll may** (D71 §5). An `inspect … 2>/dev/null
  | grep` hands back grep's status, so a dead daemon reads as "wrong network". Both scripts now
  status-check and **match docker's message, not its exit code**: docker exits 1 and prints `[]` both
  for an absent network and for an unanswerable daemon. CI drives five states of each copy, including
  the absent network as the positive control.
  Three folded reads survive on purpose; do not "fix" them:
  - the otel-collector `warn`
  - the health-wait polls
  - `deploy-dev.sh`'s `running()` (D69 §6)
- **A poll whose exhaustion is fatal needs something beside it that cannot fold.** In
  `quality/startup.sh`'s health wait, that is the `compose logs --tail=40 "$s"` just before the timeout
  `die`. `deploy-dev.sh`'s startup failure does the same.
- **`deploy-prod.sh`'s health gate** (D78, D80, D81, NEW-36, NEW-39):
  - The polls fold. On exhaustion, `gate_exhausted` asks `compose ps -a` once, through `host_run`.
    **Only one arm rolls back**: the one where the host answered and its own healthcheck agrees
    something is unready. Every other arm refuses and reverts nothing, because `rollback` needs the
    same host.
  - `{{.Health}}` is a second opinion from the daemon's in-host healthcheck. Do not drop that column
    from `--format`, and do not reorder it. **It works only because every app service in
    `docker-compose.prod.yml` inherits the `/dev/tcp` readiness healthcheck** (part 6 asserts this).
    Drop or rename that healthcheck and every blip becomes a rollback.
  - The gate takes its **phase** (`deploy`/`rollback`) and its **bound** as parameters with **no
    default**.
  - It stops at whichever comes first: `HEALTH_ATTEMPTS=24` or `HEALTH_DEADLINE=600`. The refusal says
    which one fired. 600s sits above docker's own 420s patience (`start_period 120s` + 20 × 15s).
    Re-derive that rather than quoting it.
- **`host_run` appends a sentinel line to every remote command, and the sentinel's presence is how the
  script tells which hop answered** (D75). `ssh` exits 255 both when it cannot connect and when the
  remote command exits 255, so its exit code cannot separate them. Six probes go through it, including
  the `secrets.env` readability loop, where a folded `grep` exit 2 once let preflight pass on an
  unreadable file. `$net_hint` is printed on the absence arm only.
- **`SSH_OPTS` is the only place `BatchMode` and `ConnectTimeout=${HC_SSH_TIMEOUT:-8}` are set**, and
  CI asserts that exact expression on stripped text, with exactly one `SSH_OPTS=` assignment. Without
  it an unbounded ssh connect takes 136s per call (about 4.5 hours for a blackholed host).
  `HC_SSH_TIMEOUT=0` is refused because it means unbounded. Part 7 asserts per-site coverage over the
  executed remote invocations; the `>= 2` floor is a count, not coverage. `HOST_SENTINEL` beside it is
  checked on raw text (a blank sentinel breaks behaviour that parts 1–2 drive). **Do not make the two
  checks consistent.**
- **The router is in `main()` and runs only when the file is executed** (D80). Sourcing the script
  configures it and stays inert; until D80, sourcing it deployed to production. Part 7 of
  `host-probe-attribution.sh` sources the shipped script and calls `main` and `rollback` against stubs.
  It also **executes** it, because deleting the `[[ "${BASH_SOURCE[0]}" == "$0" ]]` line makes a run
  that exits 0 having deployed nothing.
- **A scenario that sources this script must run in a child process, never in `( … ) || true`**
  (D80 §6b). A compound whose status is tested disables errexit and the ERR trap for everything inside.
- `smoke_test`'s two `/management/info` probes fold deliberately (D78 §8).
- **`deploy-prod.sh` has never run against a host** (D49). What has been verified is the mechanism,
  lifted out of the script and run against real ssh and docker.

## The rule the whole design turns on

**Derived, never stored.** In the prototype every rating, earning and payout total was computed at
render time, so no figure could drift from its source. The schema carries that over:

- `Professional` has **no** `rating` or `reviewCount` column. Both come from the `professional_rating`
  **view**, mapped by the `@Immutable` `ProfessionalRating` entity.
- A professional with no reviews has **no row in the view**, so `rating` is `null`, never `0.0`.
  `minRating` excludes unrated professionals rather than treating them as zero.
- `Category` has no `specialities` column; it is `DISTINCT` over the category's professionals.
- There is no `professional.total_earnings`. Earnings, totals and repeat rate are aggregates over
  `Ledger` joined to `Booking`. Month-to-date compares the **same slice of days** in the previous month.
- Chart endpoints return **rows, not rendered series**.

If a view gets too slow, it becomes a *materialised* view; the column still never appears.

**The deliberate exceptions** (list them, don't count them):

- `Professional.verification`, the projection of the latest `VerificationReview` (D16)
- `payment_attempt.providerReference` (D41)
- `Payout` batches (D95)

`Ledger`'s own money columns are argued in the JDL as not a contradiction. **A total across batches is
still forbidden.**

**Two CI checks hold the table itself** (D54, D59). Both derive their expected set from `jdl/*.jdl`
and never from a list:

- *"Every entity JHipster generates CRUD for must be deleted or authorized"*: each entity needs either

- *"Every generated Kafka sample resource must be deleted or authorized"*: derived from `baseName` and

Their limits (measured): the sweep only sees the `KafkaResource.java` suffix; the gate counts
`@PreAuthorize` per mapping and does not attribute them; and only the simple annotation name counts,
which fails closed. If a screen needs a resource back, gate it with a class-level `@PreAuthorize`.
Never widen a route predicate.

**Restore the two fixtures** that regeneration replaces with real test classes: `BookingResourceIT`
and `ProfessionalResourceIT`. Both need `zoneId` (and the booking needs `professionalLogin`), or four ITs
fail on a not-null constraint. `ProfessionalResourceIT` is **not a test**: it holds fixtures generated

JHipster has emitted each form in different versions.

**And `pom.xml`, in all five**: the `opentelemetry-javaagent.version` property, the

**Never name a hand-written class after one the JDL generates.** `service X with serviceClass`
generates `XService`, and hand-written code in it is replaced. That is why the booking lifecycle is
**`BookingWorkflow`**, the payout writer is **`PayoutRun`**, and `BrokerageConfigService` is left
orphaned rather than absorbing `BrokerageTerms`.

**Made regeneration-proof on purpose** (new files; nothing to re-apply):

- catalog: `SeedProperties` (`@Component`), `MarketplacePublicSecurityConfiguration`,
  `InternalApiSecurityConfiguration`, and `MarketplaceService` for the internal lookup (never a method
  added to a generated repository).
- gateway route and security: `MarketplacePublicRouteConfiguration` and
  `PaymentWebhookRouteConfiguration`. The generated `.pathMatchers("/services/**").authenticated()`
  runs before routing; without these two, public reads and provider callbacks are 401 at the edge.
  `InternalApiSecurityConfiguration` and `InternalCustomerContactResource` are D74's contact lookup,
  which **opens** a path the generated chain denies. `InternalCustomerContactResource` reads the
  generated `UserRepository.findOneByLogin` directly from `web`.
- gateway accounts (D94): `AccountRetention`, `UnactivatedAccountSweep`, `MailDeliveryGuard`,
  `MailDeliveryInfoContributor`.
- gateway metrics (D84): `GatewayIdentityMeters`, `CountingReactiveAuthenticationManager` (a
  `@Primary` decorator), `IdentityMetricsConfiguration`, `IdentityMetricsRefresher`.

Hand-written gateway classes now live in `config/`, `web/rest/`, `management/`, `security/` and
`service/`. **Enumerate them; don't count them.**

**Every hand-written security chain carries `@Order` on the `@Bean` method, never on the class**
(WP-13, D77). Spring never reads a class-level `@Order` there, so the chain order falls to
alphabetical scan order. In the servlet services, the generated `SecurityConfiguration` declares **no
`securityMatcher`**, so it matches any request, and the hand-written chains open doors it closes (an
unmatched path is 401). A mis-ordering there is loud (`UnreachableFilterChainException`); that is
deliberately not asserted. `PaymentWebhookRoutePermitIT`, `InternalApiPermitIT` and
`FilterChainPrecedenceIT` (catalog, booking) ask the running container. CI's *"A filter chain's
precedence may not be declared where Spring cannot read it"* derives services from the JDL and files
from the bean type.

### The account lifecycle (D94, NEW-47)

The generated defaults combined into a trap: `POST /api/register` answered 201 without waiting for
mail, the mail failed into one WARN, the host was `localhost:25`, the base URL was
`http://my-server-url-to-change`, and the account was deleted three days later. No message had ever
left the estate, and `MailServiceIT` mocks the sender. Now:

- **Retention is a stated policy with the same value**: `healthconnect.accounts.unactivated-retention-days`,
  default `3`. It is quoted in `docs/privacy-notice.md` §7.1 and `docs/processing-record.md` §3.1, and
  **CI refuses a build where code and documents disagree**. `0`, a negative or an unreadable value
  refuses startup. There is no "never delete".
- **The sweep registers through `SchedulingConfigurer`, not `@Scheduled`.** Compose's `${X:-}` sets an
  *empty* variable, and an empty cron is invalid, not missing. Blank-handling lives in Java.
- **`prod` requires `HC_MAIL_HOST`, `HC_MAIL_PORT` and `HC_MAIL_BASE_URL`** (`:?` in compose and a
  defaultless placeholder in yml), and refuses `localhost`. Dev and quality run mailpit, project
  network only, with SMTP unpublished.
- **No SMTP health indicator** (`management.health.mail.enabled: false`). Otherwise somebody else's
  relay outage would roll back a healthy deploy. `MailDeliveryInfoContributor` puts the state on
  `/management/info` (never the username or password, since that endpoint is `permitAll`), and the
  smoke test fails on `mail.configured`.
- **Rate limits are provided, not installed.** The zones are `hc_market_login` (1/s, burst 5) and
  `hc_market_account` (10/min, burst 3), on `/api/authenticate`, `/api/register` and
  `/api/account/reset-password/init`, via a `map` so the single `location /` is not duplicated.
  Production's zones are in `deploy/prod-server/nginx-conf.d/hc-market-account.conf` (http scope);
  quality's are in `host-site.conf`. **No ceiling is in force anywhere yet**, because `/etc/nginx` is
  the architect's.
- **`/api/activate` and `/api/account/reset-password/finish` are `permitAll` and deliberately
  unlimited** (D94 §5). CI pins that difference as an **exact** set.
- The mailed links point at frontend routes this estate does not serve (NEW-60, above).

### Gateway identity metrics (D84, D85)

- **Logins are counters and accounts are gauges.** Activation happens after registration, so the split
  has to be derived when observed. The gauges are refreshed on a timer into `AtomicLong`s, because a
  gauge supplier must not block the event loop. They start at `-1`, meaning "no refresh yet".
- **"Failed" has four buckets.** `UserNotActivatedException` survives Spring's authentication manager;
  `UsernameNotFoundException` is converted to `BadCredentialsException`. `GatewayIdentityMetricsIT`
  measures this.
- **No login, email or alias may ever become a tag.** That would mean unbounded cardinality and a
  disclosure that survives erasure. An IT asserts no other tag key exists.
- **The meters must be registered on `Metrics.globalRegistry`** (D85). The agent's bridge is a *child*
  of the global composite, so meters on the injected `PrometheusMeterRegistry` never leave the process.
  `MicrometerReachesTheGlobalRegistryIT` asserts both directions. **Do not "simplify" the bean back to
  the injected registry.**
- **The bridge is opt-in**: `OTEL_INSTRUMENTATION_MICROMETER_ENABLED=true` is set in all three compose
  files, and `observability-claims.sh` part 6 refuses its absence. `./deploy/verify-micrometer-otlp-bridge.sh`
  measures off versus on, with `jvm.*` as the control.
- `deploy/observability/hc-market-gateway-identity.json` carries a `NOT-YET-TRANSPORTED` marker, held
  by `observability-claims.sh` part 5. `GatewayIdentityMetersNamingUnitTest` pins the exposition names
  (`gateway_identity_logins_attempts_total`).

### ⚠ Generating inside an agent worktree produces a broken app, and the generator exits 0

`generators/angular/support/translate-angular.js` matches `new Minimatch('**/*{.html,.ts}')`, without
`dot: true`, against the file's **absolute** path. `**` does not cross a dot-segment, so under
`.claude/` (or `~/.cache/…`) the i18n transform touches **zero files** while printing "translating
angular application" and reporting success (D101 §2). The symptoms are raw `__jhiTranslateTag__(…)`
left in templates and thousands of prettier errors. Re-running `--force` then fails in prettier
(`Error parsing file …/home.html`), which sends you the wrong way.

**Generate in a path with no dot-segment and copy the tree in.** `package.json` comes out
byte-identical. Verify with `grep -rl '__jhiTranslate' src | wc -l` (must be `0`) and `eslint . --fix`
(must change nothing). The config is not the variable.

### Liquibase starts asynchronously in dev, and races the seed loader

JHipster defaults `application.liquibase.async-start` to true, so `SeedDataLoader` queries a table that
does not exist yet and the service comes up **healthy and empty**. All seeded services set
`async-start: false`.

### Changing a JDL entity invalidates its Liquibase checksum

Regenerating rewrites the entity's changelog, so an existing database fails with
`ValidationFailedException: 1 changesets check sum`. In dev, drop the schema. In production, write a
real migration; the generated changelog is a fresh install. To add a column, write an additive
changelog (as `meeting_link` does).

### JHipster's Kafka producer serialises bytes, not strings

The shared producer uses `ByteArraySerializer`, so sending a `String` through the autoconfigured
`KafkaTemplate` fails at publish time. `OutboxKafkaConfiguration` defines a named string template that
the publisher injects by qualifier. `spring-boot-starter-kafka` is not on the classpath, so
`KafkaProperties` does not exist; read the brokers from configuration.

### The `kafka` profile is active in every environment, and nothing names it

`application.yml` puts `kafka` in `spring.profiles.group.dev` **and** `.prod` in all five services, so
`application-kafka.yml` loads everywhere. Quality's `/management/info` shows five active profiles for
the two it asked for. A binding is live only if a **function** is bound to it: `binding-out-0` has
never existed on the broker, and `kafkaProducer-out-0` stopped receiving writes when D62 unnamed the
supplier. **Ask a running container which profiles are active; the file names don't tell you** (D59).

### A one-row aggregate comes back wrapped

A Spring Data method declared `Object[]` for a single-row query returns the list wrapped, so casting to
`Number` fails. Declare `List<Object[]>` and take `.get(0)`. See `EarningsRepository.lifetime`.

### A caught constraint violation still fails the transaction

Catching `DataIntegrityViolationException` inside `@Transactional` still fails at commit with
`UnexpectedRollbackException`, because the transaction is marked rollback-only. `saveAndFlush` only
changes *when* it throws. `FavouritesResource.add` is `Propagation.NOT_SUPPORTED` and checks before
inserting.

### `modernizer` fails the build on old idioms

`modernizer-maven-plugin` runs during `verify`, **after** the tests pass, and rejects things like
`String.format` (use `.formatted`). The symptom is `Failures: 0` followed by `BUILD FAILURE`. Look for
`Found N violations`.

### `TechnicalStructureTest` forbids `broker` from touching anything

Only `repository`, `service`, `security`, `web` and `config` may reach `domain`, and only `web` and
`config` may reach `service`. So event consumers live in `service`, not `broker`. **Nothing may reach
`config`**, so a `@ConfigurationProperties` holder a resource reads lives in `service` (for example
`PrivacyProperties`). Move the holder; never relax the rule.

### The faker collision

JHipster's dev `contexts: dev, faker` loads 30 fake rows per entity. `SeedDataLoader` sees
professionals already present and **skips the real seed**, logging `seed already present`. The symptom
is 30 professionals instead of 18.

### Compose publishes a service NAME as a DNS alias on every network it joins

`catalog`, `booking` and `gateway` are already taken on `hcnet` by sibling stacks, and docker answers
duplicates arbitrarily. So the **dev** compose services are `dev-<service>` with
`container_name: hc-market-dev-<service>`, and every intra-stack address in `docker-compose.dev.yml` is
a container name. `deploy-dev.sh` maps the short CLI names, so `--services catalog` still works.

`quality/compose.yml` does use short names (re-derive the count from D68 §3 before quoting it). They
are safe because docker's resolver answers from the **querying container's nearest network first**,
the project network, and never merges across networks. **That safety comes from network membership,
not from naming.** Joining `qualitynet` (D64) moved nothing, because every app container on it is also
on `hcnet`. If a network is added whose members are not a subset of one already joined, re-run
`getent hosts <name>` from inside a container. Don't reason from the compose files.

Databases stay **off** `hcnet` and `qualitynet`, keeping short names like `catalog-db`. The quality
`x-service` anchor (`networks: [quality, qualitynet, hcnet]`) covers the five app services only. CI
refuses any `qualitynet` member without a `JAVA_OPTS`, which keeps the databases off it.

### Grepping docker for `market` hides the dev estate entirely

The dev compose **project** is `healthconnect-dev`. Its volumes are
`healthconnect-dev_<svc>-data`, and pre-directive containers were `healthconnect-dev-<svc>-1`. Neither
contains "market". So `docker ps -a | grep -i market` shows only quality, and three readers once wrongly
concluded there was no dev data. **Filter on the project name (`healthconnect-dev`,
`hc-market-quality`), or don't filter at all.** `docker compose ls -a` names the projects.

As of 2026-09-17 no dev estate exists (NEW-31's wedged pre-D27 containers were cleared on 2026-09-10),
so the next `deploy-dev.sh up` is a genuine first run. `deploy-dev.sh` is still refused from a
worktree (D65, D67).

### `apache/kafka-native` has no shell scripts

It is a GraalVM binary with no `/opt/kafka/bin`, so `kafka-topics.sh` and CLI healthchecks fail without
explanation. `deploy-dev.sh` needs `kafka-topics.sh` on the shared broker; use **`apache/kafka:3.9.0`**.

### Spring Data does not discover nested repository interfaces

Nested interfaces get no beans (`No qualifying bean of type '…AvailabilityPlanRepository$Rules'`). Use
one interface per file. `FavouriteQueryRepository` beside the generated `FavouriteRepository` is the
pattern, because methods added to a generated repository are discarded.

### Jib's `extraDirectories` needs `combine.self="override"`, or the agent silently vanishes

JHipster's `pluginManagement` declares `<extraDirectories><paths>src/main/docker/jib</paths>`. Adding
`<path><from>…</from><into>…</into></path>` at plugin level is dropped by Maven's merge: `BUILD
SUCCESS`, and no `/app/otel-javaagent.jar` in the image. Use `<extraDirectories
combine.self="override">` and restate the permissions block, or the entrypoint loses `755`. Check
inside the image:

```bash
./mvnw -o package -DskipTests jib:dockerBuild -Djib.to.image=check:local
docker run --rm --entrypoint bash check:local -c 'ls -la /app/otel-javaagent.jar'
```

### The OTel agent: verify it instruments, not merely loads

`service:up:current` derives from `jvm_thread_count`, which the agent reports whether or not it
rewrites any class. The check that counts:

```bash
OTEL_TRACES_EXPORTER=logging OTEL_METRICS_EXPORTER=none java -javaagent:… -jar …
# then hit an endpoint and look for a SERVER span carrying http.route:
#   'GET /api/professionals/count' : <trace> <span> SERVER [tracer: io.opentelemetry.tomcat-10.0:2.30.0-alpha]
```

That recipe is **`./deploy/verify-otel-agent.sh`** (D63). It needs only a JDK and the agent jar (from
`*/target/otel/` or `docker cp` from `/app/otel-javaagent.jar`), and it reports **loading and
instrumenting separately**. It covers `java-http-server`, not `tomcat` or `reactor-netty`. Its
`--describe` constants are compared by CI against this section, so keep the variable names, `SERVER
span`, `http.route` and the jar path written here. Agent 2.30.0 on JDK 25 instruments; hc-patient's
2.9.0 loads and rewrites nothing.

**Attachment.** `docker-compose.prod.yml` attaches the agent (production has never deployed). Dev and
quality attach it only when `HC_OTEL_JAVA_OPTS` is set; unset renders a byte-identical JVM command
line. **The default stays empty deliberately** (D73 §3): `monitoring-quality` belongs to another
repository and can go down, and against a dead collector the agent writes about **35 ERROR lines per
150s per service**. Against a live collector it is quiet: measured 2026-09-10 at ERROR=0, with all
five service names in Tempo and Mimir. Quality's app services join `qualitynet` (where `otel-collector`
resolves), and `startup.sh` creates `qualitynet` if missing (D64).

The agent **is** attached on the running quality estate (`/proc/1/environ`). So
`hc-market-rules.yaml`'s header ("NOTHING ANSWERS…", "NO ENVIRONMENT ATTACHES IT") is true of the
rendered default and false of the running estate. That is NEW-72; CI holds the marker against the
render, correctly.

### Jib images have no `curl` and no `wget`

They do have `bash`. Healthchecks speak HTTP over `/dev/tcp`:

```yaml
test: ['CMD', 'bash', '-c',
       'exec 3<>/dev/tcp/localhost/8080 && printf "GET /management/health HTTP/1.0\r\n\r\n" >&3 && grep -q UP <&3']
```

`deploy-prod.sh`'s readiness gate does the same through `docker compose exec`.

### A green publish does not mean the image is in the registry

Jib once logged "Built and pushed" for all five and exited 0, while ghcr held the SHA tag for only
three. `release.yml`'s `verify` job performs the token-then-manifest handshake for each image, retrying
for about 5 minutes; if it fails, re-run the workflow. For the same reason `quality/startup.sh`
requires `TAG` and never falls back to `latest`.

### Spring Boot 4 renamed the MongoDB properties

JHipster 9.2.0 generates `spring.mongodb.uri`. `SPRING_DATA_MONGODB_URI` sets nothing, and the gateway
dies in Mongock connecting to `localhost:27017`. Use **`SPRING_MONGODB_URI`**.

### The JDK trap

`/usr/lib/jvm/java-25-openjdk-amd64` is a **JRE with no `javac`**. Use
`/usr/lib/jvm/jdk-25.0.2-oracle-x64`. An incremental build with a populated `target/classes` *passes*
under the JRE, so always verify with `clean verify`.

### Others

- **XML comments may not contain `--`**: a CLI flag in a comment breaks Liquibase parsing at a line
  number.
- **JHipster pluralises relationship names** (`services` → `getServiceses()`), so the JDL names all
  relationship sides in the singular.
- `javaVersion` is **not a valid JDL key**; set it in `.yo-rc.json`.
- Don't `pkill -f` on a pattern that appears in your own command line.

## Architecture

Five apps behind a gateway. Each owns its own database **instance** (not schema). Kafka KRaft is the
backbone and **Consul** handles discovery.

- **The broker and Consul are borrowed, never bundled** (D27). No compose file here declares either.
  Dev and quality use `hc-infra`'s plane (`hc-shared-quality-kafka:9092`,
  `hc-shared-quality-consul:8500`) over the external `hcnet`; production uses the host's `infranet`.
  Those are defaults written twice (script and compose), and CI asserts each pair matches. Do not make
  the compose copies `:?`, because CI renders `quality/compose.yml` by hand.
- **Databases are the opposite call** (D49). Production bundles them in `deploy/prod-server/compose.yml`,
  a second compose project on this product's own `hcmarketnet`, off `infranet`.
- **`deploy/prod-server/` is the install-once half of production**: data tier, nginx vhost and snippet,
  `infra.sh`, `backup.sh`, `start`, `secrets.env.example`. **None of it has run against a host**; read
  its `README.md`. The first execution of each piece is where its defects show up (`backup.sh`'s first
  run leaked both DB passwords into argv).
- **A failing smoke test rolls the deployment back**, so the catalogue check requires a *number*, not a
  positive one. Production never seeds, so `0` is warned about rather than refused.
  `HC_SMOKE_MIN_PROFESSIONALS` raises the floor.
- **Production is API-only: the prototype is NOT served on `market.abofonsa.com`.** It shows 18
  invented professionals with credentials. CI asserts that absence.
- **Gateway routes match `/services/<service>/api/**`, not `/**`, and that is a security control** (D28).
  catalog's `/internal/professionals/{ref}/login` authenticates nobody, and only the narrow predicates
  keep it private. Widening any predicate in any of the three compose files makes it public. Booking
  does mint tokens (D38, D74), but none for catalog's `/internal/**`.
- **The gateway's own `/internal/**` is NOT private by routing** (D74). It is on the gateway itself,
  both nginx vhosts proxy `location /`, and **nginx is what exposes it**: quality and production bind
  loopback; only `docker-compose.dev.yml` binds the gateway on every interface. What refuses a stranger
  is the credential (see Working here).
- **A narrow route is not a guarded endpoint** (NEW-15, D54). Every service has
  `.requestMatchers("/api/**").authenticated()`, so generated CRUD was reachable by any token, including
  every private message and the commission rate. That is why the delete table is derived and checked.
- **Consul registers; it does not route.** `discovery.locator.enabled: false` everywhere, with static
  routes. Registration needs `PREFER_IP_ADDRESS: "false"` and a per-service `DISCOVERY_HOSTNAME` set to
  the container name, because these containers have two addresses.
- **One broker, two estates, separated by a topic prefix** (D29). `healthconnect.topics.prefix`
  defaults to empty. Only `docker-compose.dev.yml` sets `dev.`, and `deploy-dev.sh` creates the
  prefixed topics from the same variable, **`HC_TOPIC_PREFIX`**. Its default is written in both the
  script and the compose file, and CI asserts the pair matches. Change one without the other and the
  apps silently sit on topics nobody publishes to. Consumers switch on the envelope `type`, never
  `record.topic()`. The prefix is applied at **send** time in `OutboxPublisher`, so `outbox_event.topic`
  stays logical.
- **The gateway runs MongoDB, and that is load-bearing** (D1). JHipster 9.2.0 uses
  `springBoot4 = !(databaseTypeSql && reactive)`, so a SQL gateway would drop to Boot 3.5.15.
- **Money is `long` minor units (pesewas)** plus an ISO currency, never `double`. The 12% fee is
  **inside** the price. Free services (`priceMinor: 0`) are real. **No provider is asked to authorize
  zero** (D44): `NOTHING_TO_PAY` creates the booking in `REQUESTED` with no `payment_attempt`.
- **Listing prices** (D100, NEW-50). A `ProfessionalCard` carries three derived values:
  - `fromPriceMinor`: the literal minimum, 0 included
  - `fromPaidPriceMinor`: the headline
  - `hasFreeService`
  
  `maxPriceMinor`, both comparators and the facet range read `fromPaidPriceMinor`. A listing with no
  paid service is **excluded** from price filters and sorts last. The facet range is `9000 → 42000`;
  quote it as a pair. The prototype always filtered `s.price > 0`, so it was the API that diverged.
- **The rate is struck when the booking happened, and the moment travels on the event** (D53). Payout
  prices against the `BrokerageConfig` in force at `bookingCompletedAt` (or `bookingCancelledAt` for a
  late fee). Booking's `OutboxRecorder` puts both on the payload. **Nothing on that path reads a
  clock.** A missing instant falls back to `occurredAt` at WARN; if both are missing the event is
  refused. Never fall back to `now`. `ledger.earned_on` stays the day the event was **consumed**
  (D51). `TheRateIsStruckWhenTheBookingHappenedTest` covers the consumer; the CI grep only checks the
  text is present.
- **The receipt is priced at the same moment through the same selector** (D56, NEW-16).
  `GET /api/internal/brokerage/split` takes `at` (an `Instant`) and `on`, and booking sends both:
  - `at` alone wins.
  - Both present: `at` wins, with a WARN if `on` disagrees.
  - `on` alone: the start of that marketplace day.
  - Neither: **400**.
  
  **Keep `on`**: an old payout behind a new booking needs it, and "`on` alone" does not warn.
  `BrokerageTerms` is the one selector (newest `id` wins ties, nulls first; returns `Optional`). CI
  checks that booking sends each parameter and that payout binds `Instant at` by its type. It also bans
  `Instant.now()` in `BrokerageResource`, and **deliberately not in `BookingEventConsumer`**, which uses
  it correctly on `ProcessedEvent`; widening the ban turned `main` red once. This path **is**
  gateway-routed and readable by any token, by design.
- **One `Booking` aggregate** replaces the prototype's four arrays. `ACCEPTED` was removed; accepting
  goes straight to `CONFIRMED`, and the topic is still `booking.accepted`.
- **`Conversation`, not `Thread`**, because `Thread` shadows `java.lang.Thread`. REST paths are still
  `/api/threads`.
- **Seed loading is double-locked**: the `test & dev` profile pair *and* `healthconnect.seed.enabled`.

**A check may not ask its question through a pipe** (D98, NEW-71). `grep -q` exits at its first match,
the producer dies with SIGPIPE (141), and under `pipefail` a match reads as failure. This depends on
the producer's stdio buffer (about 4.5 KB of stripped text), **not machine load**. Use one of two forms:
strip once into a temp file and `grep -q` the file (`has_in`), or use a herestring for text already in
a variable. `grep -c … || true` is rejected because it also discards grep's `2`. Accumulate with
`if … then var=… fi`, never `cmd && var=`, because the left side of `&&` is exempt from errexit.
Pipelines whose **output** is used, as opposed to their status, are deliberately left alone; only a
status-asking `| grep -q` is forbidden. For dropping blank lines, use `sed`, never `grep -v '^$'`,
which exits 1 under `pipefail` exactly when the answer is legitimately empty. The
remaining population is NEW-73 (50 stripped sites, 57 raw). **Fixtures for a text guard must be legal
in the language they're written in, and should plant defects at the top of a file as well as the
end.** `account-lifecycle-guards-test.sh` classifies every case as `refusal` or `control`, and refuses
to print a trailer that doesn't reconcile.

  `${VAR:?…}` expansion (bounded to its `}`). It still catches `:-` (D98 §5).
- Part 4 prunes `.claude` beside `target` and `node_modules`, because agent worktrees live inside the
  repository.

**Any check that matches source text must strip comments with `.github/checks/strip-comments.awk`,
never with its own expression.** "A check whose reach depends on prose is not a check." The stripper:

- preserves line numbering, because callers quote line numbers back
- tracks strings, char literals and text blocks (D77). The string-blind version truncated every
  `SecurityConfiguration` at `"/api/admin/**"`.
- has its caller count derived by the one-line `awk` in its own header; don't quote it from here.

**Shell scripts use `strip-sh-comments.awk`** (D68), because the Java stripper removes nothing from
shell and exits 0. The shell stripper blanks from a word-initial `#`, and keeps `${#arr[@]}`, `$#` and
`${x#pfx}`. A quoted `#` truncates the line (fails closed). `;#` is not seen (fails open; named and
tolerated). **Neither stripper guesses from the file extension.** Every caller checks that the stripper
file exists, because when it was absent, checks passed having read nothing. `strip-comments-test.sh` and
`strip-sh-comments-test.sh` assert that real code survives, as their control. Cases 6 and 12 embed the

### The prototype

- **Two modes; the default is still the closed demo** (no network). `?api=` turns on live mode (D29):

  ```
  ?api=                        same origin, served behind the estate's nginx — no CORS
  ?api=http://localhost:15509  an explicit gateway
  &token=<jwt>                 unlocks /api/stream; public reads need none
  ```
- **The seed is extracted from the FIRST script block only**, in a sandbox with no `fetch`. Live mode is
  the LAST block and mutates the data consts in place. Never move a network call into the first block,
  and never let the last block redefine what the first one exports.
  Never write a literal closing script tag inside a comment.
- Reads are live, and so are the four writes with a token. The writes omit `priceMinor`, `currency`
  and `professionalLogin`. **The professional workspace (`#/pro/…`) is not live** (NEW-8). `sendMsg`
  is rewritten, so it never fabricates a reply.
- **Adding a hero figure means saying which mode it is true in.** `p.rate` (`₵NaN`) and "Sessions
  brokered" (269 against a seeded 256) were both derived once in block 1. Live mode's
  `sessionsBrokered()` returns `null`, and the tile is omitted.
- Check it with `node deploy/verify-prototype-live.mjs http://127.0.0.1:15509` (reads only) or with
  `--writes /tmp/tok.txt` (**creates data**). It runs the shipped blocks, in order, in both modes.
- **Quality serves the prototype same-origin** at `http://market.healthconnect.local/prototype`, with a
  weaker CSP scoped to that path; `add_header` replaces rather than merges, so check an `/api/**` path
  after touching it. **`market.abofonsa.com` has `default-src 'none'` and no such location** (D49).
- **End in a real browser.** No automated check caught `₵NaN`, and only comparing against the estate's
  own counts caught 269.
  `google-chrome --headless=new --dump-dom --virtual-time-budget=25000 'http://market.healthconnect.local/prototype?api='`
  reads the hero stats; a human still has to look at the layout.
